# Memory Consolidator · 控制论反馈学习闭环

> "没有反馈的系统不是设计，是赌博。"
> 本 Skill 实现钱学森工程控制论在 Agent 记忆系统中的反馈闭环：
> 实际工作 → 短期记忆 → Dreaming 晋升 → **Consolidator 提炼** → 长期规则 + 项目导航

## 角色设定

运行此 Skill 时，以**钱学森的工程控制论视角**进行记忆巩固。不是被动整理信息，而是主动追问：
- 这段经验能抽象成什么可复用的规则？
- 这个事实应该放在项目地图的哪个位置？
- 哪条旧信息已经过时，应该删除？
- 三层架构是否一致？L1 的控制律在实际中是否被遵循？

## 输入

- `SOUL.md` — L1 控制律，作为评估标准
- `AGENTS.md` — L2 现有抽象模式
- `MEMORY.md` — L3 项目导航 + Dreaming 自动晋升内容

## 执行流程（5 个阶段）

### Phase 1: 读取现状

```
read SOUL.md    → 确认 L1 控制律（6条认知路由 + 行为边界）
read AGENTS.md  → 列出 L2 现有模式（7条抽象规则）
read MEMORY.md  → 识别:
  A. 手动维护的项目导航段（## 1-6 + Personal Context）
  B. Dreaming 自动晋升的新内容（分隔线以下）
```

### Phase 2: 评估新信息

对 Dreaming 晋升内容逐条分类：

| 分类 | 判断标准 | 去向 |
|------|---------|------|
| **可抽象为模式** | 跨领域复用、不依赖具体项目、表述为"当X时做Y" | → Phase 3 提炼 |
| **项目状态更新** | 具体项目的进展、数据、决策 | → Phase 4 压缩 |
| **重复/过时** | 已在项目导航中、或时间超过 14 天且不再相关 | → 删除 |
| **路径引用** | 指向项目本地/git/Linear 的指针 | → 合并进项目导航 |

分类时用 L1 控制律作为评判标准：
- 「先问本质」— 这段信息的本质是什么？模式还是事实？
- 「定层次」— 这是 L2 层的模式还是 L3 层的事实？
- 「能否建模」— 能否抽象成一个 if-then 规则？

### Phase 3: 提炼抽象模式 → 更新 AGENTS.md

对可抽象为模式的内容，按以下标准提炼：

1. **一句规则**: 不超过 15 个词的断言句
2. **触发条件**: 什么时候应用？（问题类型，不是项目名称）
3. **行动结构**: 怎么做？（3-5 个步骤或要点）
4. **跨域验证**: 能否在至少两个不同领域成立？

**提炼标准（Karpathy 级抽象）**:
- ❌ "Smart Saver 数据 pipeline 需要 schema → 验证 → 清洗"
- ✅ "任何数据密集型系统：定义 schema → 设验证门 → 自动化管道"

**写入 AGENTS.md 前检查**:
- 是否与现有 L2 模式重复？→ 合并，不新增
- 是否符合 L1 控制律？→ 不一致则不通过
- 是否达到"举一反三"的抽象层级？→ 不到则继续提炼

**更新方式**: 在 AGENTS.md 的 Cognitive Patterns 段末尾添加新模式，格式与现有 7 条一致。

### Phase 4: 压缩事实 → 更新 MEMORY.md

对项目状态更新，按项目导航格式更新：

1. **Status 行**: 更新当前状态（1-2 句，覆盖旧状态）
2. **Detail files**: 添加指向具体文件的路径引用
3. **不记录**: ticket 级别的进度、具体的数值变化（这些在 Linear/git 里）

对 Dreaming 内容：
- 所有已分类处理的内容 → 从 MEMORY.md 删除
- 保留的路径引用 → 合并到对应项目条目
- 完全过时的块 → 直接删除

**压缩原则**: MEMORY.md = 导航地图，不是信息仓库。每个项目条目应在 10-15 行以内。

### Phase 5: 一致性验证 + 闭环

完成后检查：

1. **L1→L2 一致性**: AGENTS.md 的每条模式是否能用 SOUL.md 的控制律解释？
2. **L2→L3 一致性**: MEMORY.md 的项目导航是否指向了 AGENTS.md 模式所需的信息源？
3. **自引用检查**: MEMORY.md 中 Agent Architecture 项目条目的状态是否反映了本次更新？
4. **Token 预算**: MEMORY.md < 12k chars（截断线以下不存重要信息）

输出**巩固报告**：
```
## 记忆巩固报告 (YYYY-MM-DD)

### 新增 L2 模式
- [模式名]: [一句话规则]
  来源: [哪个项目/经验]

### 更新 L3 项目状态
- [项目名]: [变更内容]

### 清除过时内容
- [N] 块 Dreaming 晋升内容 (日期范围)
- [M] 条重复信息

### L1 控制律验证
- [一致性检查结果]
```

## 特殊情况处理

**无新内容**: 如果 Dreaming 没有产生新的晋升内容，且项目导航不需要更新，报告 "无需巩固" 并退出。

**新项目出现**: 如果发现 Dreaming 内容涉及一个新项目（当前 MEMORY.md 中无对应条目），按模板创建新条目：
```
## N. [项目名]
Purpose: [一句话]
Context: [背景 2-3 句]
Locations: [本地路径/git/Linear/关键文件]
Setup: [配置]
Status: [当前状态]
Detail files: [进一步细节去哪找]
```

**L2 模式已达上限**: 如果 AGENTS.md 接近 12k chars，优先合并相似模式或移除最不常用的模式，而非停止提炼。

**L1 控制律可能需要更新**: 如果多次巩固后发现某种思维路由持续缺失，标记为 "建议更新 SOUL.md" 但**不自动修改**——L1 只能由用户手动更新。

## 与其他系统的关系

```
memory/YYYY-MM-DD.md (每日日志)
        │
        ▼
    Dreaming (每天 3AM, 自动)
        │  评分 + 晋升高信号内容
        ▼
    MEMORY.md (L3 底部)
        │
        ▼
    Memory Consolidator (本 Skill, 周期性)
        │  ┌─ 抽象模式 → AGENTS.md (L2)
        │  ├─ 压缩事实 → MEMORY.md 导航段 (L3)
        │  └─ 清除过时 → 删除冗余晋升内容
        ▼
    SOUL.md (L1) ← 只由用户手动更新
```

## 使用方式

用户说「跑 consolidator」「记忆巩固」「提炼模式」等触发词时，按本 Skill 执行。
也可配置为定期 cron 自动运行（建议频率：每周一次）。
